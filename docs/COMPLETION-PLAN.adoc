[IMPORTANT]

This is a planning document produced from a survey on 2026-11-04. It is not a status authority. Feature readiness lives in link:CAPABILITY-MATRIX.adoc[CAPABILITY-MATRIX], and soundness-hole status lives in link:SOUNDNESS.adoc[SOUNDNESS]. toc::[]

[abstract]
This plan builds on eight structured maps of the AffineScript compiler and its estate neighbours, produced on 2026-11-04. The repo states it covers are affinescript HEAD `5af55f5` (a shallow clone), typed-wasm `ac1bf63`, and the checkouts of the other repos under `/home/user`.

Each claim carries one of these status labels:

* *RUN*: a survey agent ran a tool and saw the result.
* *READ*: an agent inspected the source but did not execute it.
* *DOC*: the claim appears only in repo documents and was not reproduced.
* *ABSENT*: the component does not exist.

No claim is raised above the status the maps support.

An adversarial review pass checked this plan against the maps, and its corrections are folded in. The session lead also reproduced four headline findings directly on the built compiler: H1 (the interpreter returns 2 for `g(5)` where WebAssembly returns 1), H4 (a non-exhaustive match type-checks and the compiled WebAssembly returns 0), H6 (`check` reports a borrow error on two #554 fixtures that `eval` runs into a runtime type error) and H8 (`total fn loop` type-checks). Proof claims about Idris2 artefacts stay at READ or DOC everywhere, because no survey agent could install idris2. The systemet repo was not checked out, so every theory-level claim attributed to it is unverified.

== 1. Ground-truth snapshot

=== 1.1 Caveats on the snapshot itself

* Toolchain state differed between survey containers. For example, the typell agent found no OCaml, while the compiler agents installed it from apt and built. Treat the provisioning in workflow W0 (section 7) as mandatory, not optional.
* Several proof checks ran on toolchain versions different from the CI pins:
** Agda 2.6.3 versus the CI pin 2.6.4.3. stdlib 2.3 versus the 2.1 pin, which applies to choreographic-types only; echo-types itself pins stdlib 2.3.
** Coq 8.18 versus CI 8.20.1.
+
Results were consistent, but they do not prove CI is green.
* `tools/check-soundness-ledger.sh` cannot run on the shallow clone because stamp `65c2ae3` is missing from history. So the ledger itself is unverified this session.
* Parallel agents contended for apt locks. One install was silently lost and had to be retried.

=== 1.3 Unledgered silent holes found by this survey (doctrine 1: these come first)

All were observed by RUN unless marked otherwise. The maps confirm that H1–H4 and H9 are absent from `docs/SOUNDNESS.adoc`. H5–H8, H10, H12 and H13 were not checked against the ledger. H11 already has a drafted issue (`issues-drafts/06`, referenced from the AFFIRMATION). H14, H15 and H19 belong to typed-wasm, not the AffineScript ledger.

. H1. Interpreter early `return` has no non-local exit (`lib/interp.ml:262`).
. H2. Bun-ESM `return` in expression position is lowered as an IIFE (`lib/codegen_deno.ml:1575`). *Narrowed 2026-11-09:* `let` initializers and function and lambda tails are now lowered to statements, so the `return` leaves the function; a match used as an argument or operand with a `return` in an arm is refused loudly. Anchor: `test/test_module_root_flatten.ml`.
. H3. The JS-text backend drops block returns (`lib/js_codegen.ml`). The Lua backend emits invalid code.
. H4. Non-exhaustive match compiles to "return 0" on core WASM.
. H5. Effect rows are not checked against performed operations or callee rows.
. H6. `eval` and the REPL skip borrow checking and trait coherence. Only the `eval` borrow-checking gap is RUN. The REPL gap is READ only, because the REPL is not built.
. H7. Interpreter `let mut` reassignment fails at runtime.
. H8. `total fn` is accepted without any check.
. H9. Integer width diverges: the interpreter uses 63-bit ints, WASM wraps at i32.
. H10. `compile` emits a `.wasm` despite typed-wasm L7/L10 violations.
. H11. `own` is mapped to the Linear ownership kind (READ).
. H12. The QTT anchor tests are vacuous.
. H13. `wasm-validate-gate` SKIPs with exit code 0 when `wasm-tools` is absent.
. H14. The typed-wasm verifier fails open: empty modules pass (RUN); unknown versions and unknown bytes pass (READ).
. H15. typed-wasm `tw build` stub miscompile. This is in the typed-wasm repo, not AffineScript.
. H16. The AffineScript front-end accepts L7/L10-violating programs (c5_real `03_partial_drop.affine`).
. H17. The lexer accepts the bad escape `\q`, and an empty `match` parses (conformance invalid cases 010 and 011).
. H18. The interpreter fails when dereferencing refs returned through calls ("Expected reference type"). The session lead reproduced this on two #554 fixtures.
. H19 (typed-wasm). No L5 index guard: `get_player_hp(0,150)` reads an adjacent region. `where` constraints are discarded. Malformed `session` blocks are silently ignored.
. H20 (found and fixed 2026-11-09, checking and running metadatastician/kyq). A module file found for `A.B` that declares `module A;` was accepted as `A.B`, so `use A.Nonexistent::*` type-checked and imported `A`'s exports; it is now a `ModuleDeclMismatch` load error. Anchor: `test/test_module_root_flatten.ml`.
. H21 (found and fixed 2026-11-09). `eval` ran the unflattened program, so no imported function was bound at run time; flattening also emitted a selected function before the private helpers it calls and carried no helpers for glob or plain imports. `eval` now flattens, every import kind carries its helpers, and they are emitted in the imported module's declaration order. Anchor: `test/test_module_root_flatten.ml`.
. H22 (found and fixed 2026-11-09). The interpreter had no `++` on arrays and no `==`/`!=` beyond Int, Float, String and Bool, though the checker accepts them; it now uses the structural `Value.value_eq`. H7 (`let mut`) is unchanged. Anchor: `test/test_module_root_flatten.ml`.

*Design principle.* Exactly one path is trusted: source, then the shared checking pipeline, then core WASM, then fail-closed typed-wasm-verify, then a runtime.

Every other backend is labelled experimental until it passes the differential harness described in section 4.

The kernel enters first as an independent oracle for translation validation, and only later as the certified core. This follows from section 6, fork F2.

=== 5.1 Solver and automation options

* *SMT for QTT.* Usage counts become linear integer constraints with `ω` as an unbounded tag. Z3 is apt-installable (4.8.12, RUN in the absolute-zero cluster). This gives a second, independent oracle beside anytype, at a fraction of the Idris cost.
* *Datalog for borrows.* Polonius facts are already extracted (`lib/borrow_extract.ml`). Running an external solver turns the existing test-only machinery into an N-version check.
* *Translation validation instead of a verified compiler.* Per-output carrier checking (P1) checks ownership and access-typing annotations on each emitted `.wasm`, not semantics. Differential checking against Coq (P2) runs at test time for the int/bool/let/if fragment only. Neither proves the 3987-line `codegen.ml`.
* *Auto-generated `Print Assumptions`.* Generate one line per lemma, as done in the survey's `AllAssump.v`. This closes the axiom-gate blind spot at near-zero cost.

=== 5.2 Where a type, logic or proof trope gives a more final solution

* *de Bruijn criterion / LCF kernel.* The elaborator, which is untrusted, produces core terms. A small kernel (anytype `Core/Check.idr`) re-checks them. Correctness then rests on the kernel, not on `typecheck.ml`. This is the principled end state of P3.
* *Proof-carrying code via the typed-wasm carriers.* The compiler emits certificates (ownership, access typing, and later cost or occupancy grades) that a small checker validates. typed-wasm is already this shape. The final step is to extract the checker from Idris `decAccessTypingClean` instead of transliterating it.
* *Evidence-passing translation for handlers (Xie–Leijen).* This compiles tail-resumptive handlers to plain calls, removing the CPS dilemma (#623) for the common case.
* *Separation logic (Iris-style) for borrows.* This would make P5 compositional. It is a large investment; label it as research.
* *Grade-polymorphic checking: "pick the algebra, get the discipline".* Functorise `quantity.ml` over a grade signature so that QTT, cost and other grades share one proof. The existing algebras must be split into two classes: the non-idempotent QTT semiring, and idempotent ⊕ grades (Loss, HWM, MaxPlus).
